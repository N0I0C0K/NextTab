# NextTab Code Review

发现有证据支持、影响实际行为的问题，给出可执行的修复方向。审查深度随变更风险调整；测试通过不能替代代码审查，无发现也不等于证明没有缺陷。

## 确定范围

- 优先使用用户指定的 PR、提交、分支或文件范围；未指定时审查当前工作区变更。用 `git status --short` 确认状态，结合 `git diff`、`git diff --cached` 和新增文件内容，避免漏掉未跟踪的实现和测试。
- 阅读适用的 AGENTS.md、相关调用方与测试。产品行为以用户最新决定和 [设计要求](../../../doc/DESIGN_REQUIREMENTS.md) 为依据，构建与测试入口见 [DEVELOPMENT.md](../../../DEVELOPMENT.md)。发现文档与实现冲突时注明依据，不自行改变产品规则。
- 区分本次新增缺陷与已有问题。已有问题仅在被变更放大、阻断本次行为或用户要求时纳入；不要顺便扩大到整个仓库重构。

## 判定与证据

- 沿实际调用链检查“触发条件 → 状态变化 → 用户影响”，检查失败与恢复路径，而不只看正常返回值。
- 优先复用现有测试或做最小、隔离的复现。未执行的推断明确标注，不能称“已复现”；有待验证的问题与确定缺陷分开。
- 按影响和发生条件确定 P0–P3，给出绝对文件路径及最小行号范围。避免把个人风格、假设的新需求或没有实际损害的可能性当成 bug。
- 每项说明具体触发条件、为什么会出错、影响、证据及修复方向。只有“可能有竞态”“增加缓存”等泛化建议不算 finding。

## 按变更选择专项检查

以下是本项目容易漏掉的边界，检查相关项即可：

- **前台事件与停留**：快速 A → B → A、窗口失焦／恢复、后台窗口、同一 tab 导航／关闭、worker 恢复。核对事件发生时间与异步 API 返回时间；进入／离开应配对，离开期间不算停留，查询时校正不能虚构历史记录。
- **失败恢复与设置**：初始化 Promise 拒绝后是否能恢复；队列是否被一次失败永久阻断；取消或旧请求是否能覆盖新结果；成功读到设置前是否会绕过用户关闭功能的选择。重试必须有明确触发条件，避免无限循环。
- **数据隔离与身份**：当前 Profile、普通／无痕窗口、不同 origin／path、查询参数变体及多个同页标签。核对日志、标签查询、推荐、详情和导出使用一致的边界，不能从缺失字段猜测状态。
- **推荐与刷新**：对照当前评分规则，检查按日贡献、时间窗口、衰减、基础分和最终分、重复标签加成；不要重新引入已取消的筛选门槛。首页重新进入要更新，用户操作列表时保持顺序；读取失败保留旧结果，过期请求不能回写。
- **界面与列表**：主／次操作点击范围、hover 与键盘聚焦、嵌套弹窗焦点、滚动与留白。搜索应覆盖全部候选，分页只限制挂载；标签状态更新后切换／关闭动作仍有效。产品取舍与可复现交互缺陷分开报告。
- **日志与性能**：区分原始 events、配对后的统计和当次排序状态；未知数据不能冒充 0，诊断不能无界输出。检查每请求的 API 调用数、每行重复解析和对象保留；耗时、内存或低配结论需要测量支持。

## 与其他审查衔接

正确性审查与 [ponytail-review](../ponytail-review/SKILL.md) 分开执行。涉及复杂度取舍或用户要求简化时，读取该 skill，按其格式报告可删除的代码及替代方案；它的范围只有过度设计，`Lean already. Ship.` 不能代替正确性审查结论。

需要性能分析或复测时使用 [nexttab-performance](../nexttab-performance/SKILL.md)，复用既有基准和结果口径，不把审查时的猜测写成性能结论。一般 review 不必重跑整套性能测试。

用户要求独立 sub agent review 时，将范围、当前产品约束和只读要求交给审查者；不要先告诉它希望发现什么。审查者默认只给意见，主 agent 负责判断和按授权修复。给出可复用的任务说明，例如：

> 只读审查当前指定范围，包含新增文件及相关调用链，重点验证实际正确性与失败恢复。报告可复现问题、优先级、绝对文件路径和行号，区分缺陷与可选简化。不要修改文件；未运行的验证请明确说明。

## 修复、复核与交付

- 用户只要求 review 时交付意见；用户已授权修复时逐项确认，采纳的实施最小改动，不采纳的说明代码或产品依据，不重复请求已有授权。
- 缺陷修复优先验证可观察的回归行为，测试故障后的恢复、真实事件边界或用户操作，不为措辞和实现细节添加镜像测试。保留用户原始日志，不改时间戳来制造通过结果。
- 按改动运行必要检查：逻辑／状态用单测，扩展 API 或交互用相关 E2E，类型与构建按影响选择。纯文档或 skill 变更验证结构、引用和格式即可；通过后不无故反复运行全套检查。
- 修复后复核原触发路径及相邻边界；已使用独立审查者时，可让其复核最终变更。用户未授权新的独立审查时，不因使用本 skill 自动启动 agent。
- 交付时先列尚未解决的缺陷，再说明已修复与未采纳项、验证结果和实际限制。无高置信度问题时直接说明审查范围与未覆盖项，不编造 findings 或宣称所有问题都已排除。
