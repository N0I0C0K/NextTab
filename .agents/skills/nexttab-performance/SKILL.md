# NextTab 性能复测

复用项目基准 [tests/performance/return-pages.mjs](../../../tests/performance/return-pages.mjs)，不另写一套评分公式或用 Node 计时替代浏览器计时。先读 [性能报告](../../../doc/RECOMMENDATION_PERFORMANCE.md) 的最近一轮结果和限制，再按本次变更选取有意义的场景。

## 执行与产物

- 从仓库根目录运行 `pnpm test:perf <唯一标签>`，例如 `pnpm test:perf open-tabs-20261003`。命令先构建生产扩展，再执行基准；只分析算法而直接运行脚本时，也应确认界面使用的生产构建已更新。
- Playwright Chromium 与 Node 子进程需在当前沙箱允许的权限下运行。缺少 Chromium 时使用项目已有的 Playwright 安装入口，不修改用户浏览器 Profile。
- 使用独立 Chromium、临时扩展 Profile 和合成数据。需要真实导出日志回放时另行记录，避免把私人网址写入公开报告或 skill。
- 结果保存到 `artifacts/performance-return-pages/<标签>.json`。保留旧结果，记录源码 hash、环境和测量时间；不要把不同版本的文件重命名成新结果。

## 覆盖与口径

当前基准覆盖以下场景，变更相关结构时维护它们：

- 100／1,000／2,000 页的分散事件及单页高频事件，且序列化内容在实际 2 MiB 上限内；同时测正常评分和诊断评分。
- 真实 IndexedDB 的快照读取＋评分、进入／离开写入、全部及部分过期清理、容量淘汰。
- 100／2,000 个候选与 0／100／1,000 个标签结果的最终排序，包含同路径不同查询参数、多个窗口和只有标签的页面。
- 完整推荐查询的 API 调用次数及最近常用的并发上限，区别标签查询、历史明细查询和纯计算成本。
- 生产界面的首页可用、查看全部、全量搜索、长任务、挂载行数和 GC 后 JS 堆；0 和 1,000 个标签结果分别测量，不能仅测空标签集合。
- 原速与 6 倍 CPU 降速。同步操作预热后多次采样，报告样本数、中位数、P95、最大值；每个数据场景首次评分单列，不等同浏览器或扩展冷启动，6 倍阶段也复用了此前的 JIT 状态。单次界面／清理测量只能称本次耗时。

必须保留的解释边界：

- CDP 降速作用于测量页 renderer，不能等同于低配实机、慢磁盘、低内存或已降速的扩展后台 worker。
- 历史 API 和大量标签使用替身时，只能说明 API 响应后处理和调用数量；不代表真实历史磁盘延迟，也不代表真实开着 1,000 个页面时的浏览器总资源。
- GC 后 JS 堆是单页面的 JavaScript 存活对象，不是该标签的全部内存；2 MiB 是日志序列化预算，不是磁盘或内存预算。
- 耗时采样受 JIT、GC 和宿主负载影响。小差异不能直接称性能提升；出现明显退化时先复核计时范围与数据，再定向复测。

## 分析与收尾

用 E（事件）、P（候选页面）、H（历史 URL）、V（访问记录）、T（标签）描述时间及额外空间上界，检查是否对每页重复查询或对每行反复解析所有标签。将评分、存储等待、API 等待和渲染分别归因，不能拿异步总耗时当主线程阻塞。

依据结果处理瓶颈：分页、集合匹配或去掉重复工作优先；只有测量支持时才引入 Worker、缓存失效层或额外依赖。若修改了产品代码，运行对应单元／E2E 回归，再重测受影响的性能场景。

把本轮场景、结果、源码版本及限制写入性能报告，保留历史章节；在回复中给出关键结果、review 取舍、未覆盖条件和报告链接。无需为每个纯耗时数值增加固定阈值断言，保留预算、并发、去重、候选完整性和分页挂载等可重复的正确性检查。
